OpenChamber 离线交付包
=======================

版本号以 tarball 文件名为准（openchamber-*-<version>.tgz）。安装脚本从随包的
SDK tarball 读取版本号，换新版本 zip 不需要改脚本。

包内容
======
- openchamber-web-<version>.tgz  @openchamber/web，服务端 + `openchamber` 命令，
                                已把 @openchamber/sdk 打进包内
- openchamber-sdk-<version>.tgz  @openchamber/sdk，带类型定义的 guest SDK
- install.ps1 / install.sh       Windows / Linux、macOS 一键安装与原地更新脚本
- RELEASE-NOTES.md               本版本更新内容
- INSTALL.txt                    本说明

要求：Node.js >= 24.14.0（engines 字段会强制检查）。除包内自带的 SDK 外，
其余运行时依赖（@opencode/client、@opencode/schema、express、node-pty 等）
需要能从本机 npm 缓存或内部镜像解析，见“安装”。

快速安装 / 更新（推荐）
=======================
解压后按平台执行脚本。脚本会安装 tarball（缓存优先，失败回退常规安装）、
创建数据目录、可选写入机器策略文件和环境变量、打印更新内容和启动命令；
检测到已有安装时原地更新。

Windows（PowerShell 5.1 及以上）：

    powershell -ExecutionPolicy Bypass -File .\install.ps1

Linux / macOS（bash）：

    bash install.sh

参数说明：Windows 用 `install.ps1 -?`，Linux 用 `bash install.sh -h`。
常用参数：

    -Registry / --registry <url>        通过内部 npm registry 安装
    -NpmRegistry / --npm-registry <url> 固定内网 npm 镜像（写策略文件和环境变量）
    -Organization / --organization <名> 生成企业模式策略
    -PolicyFile / --policy-file <path>  放入组织提供的 policy.json（需管理员/root）
    -Port / --port <n>                  持久化 OPENCHAMBER_PORT
    -UiPassword / --ui-password <密码>  持久化 OPENCHAMBER_UI_PASSWORD
    -OpenCodeHost / --opencode-host <url>
    -OpenCodePort / --opencode-port <n> 连接外部 OpenCode 服务
    -Start / --start                    安装后拉起服务
    -DryRun / --dry-run                 只打印动作，不做修改

安装
====
web 包自带 @openchamber/sdk，只装 tarball 即可，不需要先发布 SDK，
内部 registry 没收录 @openchamber/sdk 也不影响：

    npm install -g ./openchamber-web-<version>.tgz

其余依赖仍要从 registry 解析。内网环境二选一：

A. 内部 npm 镜像（推荐）
    npm install -g ./openchamber-web-<version>.tgz --registry <内部镜像地址>

B. 预填 npm 缓存
    在能联网的机器上安装一次同一版本，把 npm 缓存目录复制到内网机器，
    再用缓存优先模式安装：
    npm install -g --prefer-offline ./openchamber-web-<version>.tgz

也可以先把两个包发布到内部 registry，再按包名安装：

    npm publish openchamber-sdk-<version>.tgz --registry <内部镜像地址>
    npm publish openchamber-web-<version>.tgz --registry <内部镜像地址>
    npm install -g @openchamber/web@<version> --registry <内部镜像地址>

配置
====
1. 数据目录（首次启动自动创建）
   默认：Windows %USERPROFILE%\.config\openchamber，Linux/macOS ~/.config/openchamber
   可用 OPENCHAMBER_DATA_DIR 覆盖。
   内含 settings.json（应用设置，由 UI 写入）、extensions\（已装插件）、
   secrets\、remote-clients.json。

2. 策略文件（配置内网环境与企业参数）
   首次安装时，安装脚本会自动在用户数据目录生成带完整中文注释的 policy.json，
   默认开启企业模式，并预留内网常见配置（可直接用普通文本编辑器修改并保存，热重载生效）。
   安装包内随附 policy.example.json 样例文件供随时对照参考。

   查找优先级：
   - 用户数据目录（优先，无需管理员权限）：
     Windows：%USERPROFILE%\.config\openchamber\policy.json（或 $OPENCHAMBER_DATA_DIR\policy.json）
     Linux/macOS：~/.config/openchamber/policy.json（或 $OPENCHAMBER_DATA_DIR/policy.json）
   - 系统管理员路径（回退）：
     Windows：C:\ProgramData\OpenChamber\policy.json
     Linux：/etc/openchamber/policy.json
     macOS：/Library/Application Support/OpenChamber/policy.json

   支持的键包括：enterpriseMode、organization、npmRegistry（内网 npm 镜像）、
   allowedInsecureGitOrigins、modelsDevUrl、skillsCatalogSources、
   allowNetworkAccess、allowedExtensions、allowLocalExtensions、
   relayUrl、jev { url, ... }、opencodeBinary、hideBuiltinSkillCatalogs。
   文件采用标准 JSON 格式（使用 _comment* 字段提供中文配置说明与示例，同时兼容 // 与 /* */ 注释），
   可选字段留空（"" 或 []）即表示不启用；每次使用时重新读取（改完不用重启），内容损坏时按“全部关闭”处理。

3. 环境变量 / 命令行参数（都可选）
   OPENCHAMBER_PORT 或 --port       监听端口（默认 3000）
   OPENCHAMBER_HOST                 绑定地址（默认 127.0.0.1）
   OPENCHAMBER_UI_PASSWORD 或 --ui-password
                                    UI 密码；对其他机器可达时必须设置
   OPENCODE_HOST / OPENCODE_PORT / OPENCODE_SKIP_START
                                    连接外部 OpenCode 服务
   OPENCHAMBER_NPM_REGISTRY         插件元数据与版本检查使用的 npm 镜像
   OPENCHAMBER_TUNNEL_MODE / OPENCHAMBER_TUNNEL_TOKEN / OPENCHAMBER_TUNNEL_CONFIG
                                    Cloudflare tunnel 选项（企业模式下拒绝启用）

启动
====
    openchamber                                   # 3000 端口，仅本机访问
    openchamber serve --lan --port 3000 --ui-password <密码>
    OPENCODE_HOST=http://host:4096 OPENCODE_SKIP_START=true openchamber

开机自启：openchamber startup enable --port 3000
（Linux 写 systemd 用户服务，macOS 写 LaunchAgent，Windows 注册计划任务。）

自己写系统级 systemd 单元时必须用 serve --foreground 启动：默认模式下 CLI
派生后台进程后立即退出，配合 Restart=always 会不停拉起新实例。

OpenCode 需已在运行（opencode serve），或由 OpenChamber 自行拉起托管实例。
启动后打开 http://localhost:3000。
