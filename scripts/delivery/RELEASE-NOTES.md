OpenChamber 2.10.3（2026-11-20）

新功能
  - GitLab：/gitlab-issue 改为打开确认弹窗再提交议题；议题可自动派发并创建 MR，
    AI 机器人与 GitLab 用户共用一个账号
  - GitLab：新增审查门、审查模型与自动化运行面板，看板新增运行卡片；
    项目级可设置审查模型和议题模板
  - 提示词增强：输入框新增魔法提示词按钮，用小模型路由和回退增强草稿；
    空草稿不显示按钮，提供方拒绝连接时立即失败
  - 分享页面：智能体可把页面发给同事填写，回答带通知回到会话；
    粘贴分享链接可在本地打开页面
  - 浏览器：智能体可在面板里点击、输入、拖动和上传文件，也能处理页面弹窗；
    标注评论支持语音输入，PDF 支持区域和画笔标记
  - 子代理：工作状态里每个子代理显示当前步骤，新增 Subagents 面板列出全部子代理
  - 聊天：可多选消息一起复制为 Markdown 或保存为图片；附件在输入框中显示为文字里的标签，
    删除标签即移除附件
  - 智能体：可等待计时器或 PR，可读取终端面板，/btw 能看到当前正在运行的回合
  - 搜索：侧栏、归档与命令面板共用一个搜索，按标题和消息正文查找，归档结果单独分组
  - 手机：扩展的界面块、工作状态段落、弹窗和文件编辑器可在手机上使用；
    屏幕在会话运行时保持点亮
  - 桌面：安装包减少约 170 MB，内置 OpenCode 服务替代完整命令行程序
  - CLI：schedule update 只改指定字段，--target-session 在已有会话中运行定时任务

改进
  - 桌面：启动更快、占用更少内存，长回合不再让侧栏持续忙碌
  - 聊天：发送与停止共用一个按钮，流式回复滚动更平滑，长草稿输入跟手
  - 连接：短暂断线后自动补上遗漏消息，无需刷新页面
  - 侧栏：会话切换器列出最近最多 10 个会话，项目名称与 worktree 图标更清楚
  - GitLab：12.7 老实例的评审能力降级并保持字段兼容，低于 15.7 回退到 /changes 读取 MR 文件
  - 工作树：引导命令分阶段执行，修好 Windows 引号问题

修复（节选）
  - 启动：设置仍指向旧版内置 OpenCode 时不再报「Configured OpenCode binary not found」；
    损坏的项目列表不再阻止服务启动
  - 聊天：超长推理块不再冻结页面，句号和问号前的反斜杠不再丢失，
    图片发给纯文本模型改为文件路径
  - 会话：软链接目录下的会话不再从侧栏消失，服务端断开后不再一直显示已连接
  - Git：Git 2.20 下 fetch --atomic 有回退且不再传 --path-format=absolute，
    大仓库的状态与 checkout 保持响应
  - 企业模式：离线 zip 包不再被门控拦截
  - 技能：create-issue 的 --ai-ready 先读后整体写 labels，避免并发覆盖

内网与低版本 Git 适配（本包定制）
  - 保留原有兼容：range-file-versions 去掉 --end-of-options；
    sparse-checkout 缺失时回退全量检出；GIT_CONFIG_GLOBAL 不可用时 HTTPS 与匿名传输隐藏 HOME
  - Git 2.20：fetch --atomic 回退，worktree pin 探测修正，不再传 --path-format=absolute
  - GitLab：低于 15.7 回退到 /changes 读取 MR 文件；12.7 老实例评审能力降级并保持字段兼容
  - 企业模式：离线 zip 包免门控

说明
  - 依赖与桌面内置 OpenCode 组件更新到 2.3.2；本次包含上游 2.7.1、2.7.2、2.7.3
    和本地 2.9.0、2.10.0、2.10.2 的改动
  - 本包同时包含内网定制能力：本地议题系统、企业模式与用户目录 policy.json、
    内网 Git HTTP 白名单、模型元数据内网地址、企业技能目录与隐藏内置技能库、
    内网 npm 镜像、Git 2.20.x 低版本兼容、GitLab 老实例探测，
    以及带中文注释的 policy.example.json 样例
  - 随包安装的技能为 gitlab-issue-create，安装脚本把它放到用户级 skills 目录
  - 本包安装脚本（install.ps1 / install.sh）全程无需管理员/root：策略文件与环境变量都写在
    当前用户目录；npm 全局前缀若指向不可写的系统目录，脚本只复用已有的用户级 npm 目录，
    不改写 .npmrc 等 npm 配置
  - 安装、配置与启动命令见 INSTALL.txt。更新后需重启 OpenChamber 服务，旧进程仍运行旧代码

上一版：OpenChamber 2.8.0（2026-11-10）

新功能
  - 扩展：扩展可声明 contributes.links，把智能体回复和用户消息里的标识符、链接变成可点标签，
    点击可打开扩展或作为引用送入输入框。links 是独立能力，有单独授权行，范围变化会重新征求同意
  - 模型提供方：设置 > 模型提供方新增 Logo 区，任意提供方可上传 PNG、JPEG、WebP 或 SVG
    图片（≤1 MB）；扩展也可随包提供提供方 logo（contributes.providerLogos），
    展示优先级为上传的 logo、选定的图标、扩展提供的、内置与 models.dev
  - 聊天：粘贴 issue 或 PR 链接会变成消息里的标签，链接详情随消息一起交给智能体
  - SDK：会话记录新增运行中的工具、上下文占用、In work 状态与未读数；
    仅有整页面的扩展不再必须附带侧栏面板；manifest 解析失败时安装错误带上解析器给出的原因
  - 会话：问 Jev 前先读本轮改动过的文件与仍在跑的后台工作，只描述未改动的回合不再给出审查提议；
    「看起来完成」提示改为回合结束后静默 10 分钟才出现，新消息或新回合会取消它

改进
  - 桌面端：一次往返才算一次 ping
  - 项目：链接到已添加项目的文件夹，在 Add project 里显示为已添加
  - Nix：内置 OpenCode 恢复启动，会话与模型可加载
  - 文档：项目知识从 agent memory 迁到 skills 与模块文档

修复（节选）
  - 启动：被拒绝信任的文件夹不再阻塞启动，并可在之后再次请求信任
  - 扩展：manifest 非法时说明具体原因
  - 聊天：子代理的界面块按块绘制，不再显示源码
  - Web：空闲服务端 socket 保留时间调到高于反向代理连接池，反代后连接不再被提前断开
  - 模型：同一家族的模型按最新版本发布
  - CLI：OpenCode 从当前登录 shell 的 PATH 解析，登录后新装的版本能被找到
  - 测试：workflows 的四个运行时测试在机器繁忙时不再失败

内网与低版本 Git 适配（本包定制）
  - range-file-versions 接口去掉 Git 2.24 才引入的 --end-of-options；
    CentOS 7 自带 Git 2.20.1 下该接口不再报错
  - 从 Git 仓库安装技能时，若 sparse-checkout 子命令不存在（Git 2.25 之前）则退到全量检出，
    选中的技能目录仍能安装；扫描路径保持原有的 ls-tree 降级
  - GIT_CONFIG_GLOBAL 需要 Git 2.32，旧版会忽略该变量：HTTPS 与匿名传输靠隐藏 HOME 兜底，
    SSH 保留 HOME 供 known_hosts 使用，此时本机 ~/.gitconfig 仍会被读取，
    url.*.insteadOf 之类的配置可能生效
