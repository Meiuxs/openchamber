## 本地 issue 分享链接（提交 `397e4bd8`，28 files +405/−72）

### 问题定性
`local/tracker.js` 的 `itemUrl()` 硬编码 `https://openchamber.local/tracker/local/<ID>`：无 hosts 记录、无服务端路由，**它只是标识不是地址**（`matchUrl`/`session-link`/`matchTrackerUrl` 靠它做粘贴识别，不能改成真实 origin）。UI 却把它当外链渲染 → 复制出来是死链；`TrackerItemView` 读取失败时还会 `openExternalUrl(url)` 直接丢给系统浏览器。

### 修法（保留标识形态，另加可导航形态）
- 契约新增 `capabilities.externalUrl`：Linear `true`、Local `false`；UI 的 zod 用 `z.boolean().catch(false)`，**缺省读作 false**（旧 server 不声明时宁可走应用内，也不给死链）。
- 路由新增 `?reference=<item url>`：`parseRoute` 只收 http(s)，`hasRouteParams` 计入；`lib/router/referenceLink.ts` 的 `referenceLinkHref(itemUrl, page?)` = 当前页地址 + `?reference=`（保留 origin/端口/tunnel host/鉴权参数），非 http(s) 页（`openchamber-ui://`、webview file://）返回 null。
- 消费端 `components/sourceBoard/TrackerItemRouteOpener.tsx`（挂在 `RuntimeAPIProvider` 内）：**首帧就读取参数**（`useRouter` 挂载后会重写地址栏），等 tracker registry 就绪后调 `useShowTrackerItem` 打开面板 tab，成功后 `history.replaceState` 去掉参数。
- 预览：`externalUrl` 为假时不渲染外链 anchor，复制按钮复制应用内链接，文案「复制应用内链接」（15 语区）；`TrackerItemView` 不再回退系统浏览器。
- 规格 v2.4：决策 22、FR-17、§12 第 9 条、§10 测试矩阵；`local/DOCUMENTATION.md` 增「Why the item URL is not a page」。
